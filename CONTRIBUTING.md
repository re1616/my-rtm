# Taskly — правила работы для агентов

## 1. Упал тест → сначала проверь код

При падении теста:
1. Прочитать реализацию, которую тест проверяет.
2. Убедиться, что код корректен.
3. Только после этого менять ожидание теста, с обоснованием в commit message.

Без обоснования менять ожидание запрещено. Тесты безопасности не ослабляются — если падают, исправляется код.

## 2. «Готово» — только со ссылкой на зелёный CI

Любой отчёт о завершении должен содержать ссылку на зелёный прогон CI в GitHub, подтверждающий изменения на целевом коммите main.

Без зелёного CI задача считается незавершённой. Имитация данных из головы — причина аннулирования всего отчёта.

## 3. Не верить отчётам агентов на слово

Если агент (coder/integrator) сообщает о готовности, проверить код и CI самостоятельно, прежде чем переносить чек-лист в «готово».

Изменения в shared-модуле (парсер, RRULE, язык запросов) требуют прогона тестов на обеих платформах (JVM + JS).
